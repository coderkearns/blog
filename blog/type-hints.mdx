## What are Type Hints?

Python is a dynamically typed language, meaning that you don't assign specific static types to variable as you code.
While this creates an ease-of-use not found in other programming languages, it can lead to ambiguity in some situations.

Consider the following Python function, meant to add two numbers together.

```python
def add(a, b):
    return a + b

add(2, 2) # 4
add(3, 5) # 8
add(4, -2) # 1
```

Pretty straightforward.

However, because these variables can be any type, this can cause errors if we don't understand what the function is doing internally.

```python
def add(a, b):
    return a + b

add(2, 2) # 4
add("Hello ", "World!") # "Hello World!"
add("Hello", 2) # TypeError: can only concatenate str (not "int") to str
```

We don't want to require our users to understand how all our functions work internally.
To solve this, Python 3.5 was released in September 2015 with [PEP 484: Type Hints](https://peps.python.org/pep-0484/).
A type hint is a special [function annotation](https://peps.python.org/pep-3107/) that tells users what data type is required as an input or output:

```python
def add(a: int, b: int) -> int:
    return a + b
```

You'll notice that this doesn't *require* users to obey the type hint, but it does communicate what the function author expects.
This also will provide [Intellisense](https://code.visualstudio.com/docs/editing/intellisense) (autocomplete, hover-tooltips, and errors if the types are violated) in most code editors.

A python type hint can be any valid data type, including compound types:

```python
class Grid:
    def draw_point_at_coordinates(coords: tuple[int, int]):
        x = coords[0]
        y = coords[1]
        ...

my_grid = Grid()
coords = (2, 3)
my_grid.draw_point_at_coordinates(coords) # x = 2 and y = 3
```

Custom types and classes also work:

```python
def show_grid(grid: Grid):
    ...

my_grid.draw_point_at_coordinates((1, 1))
show_grid(my_grid)
# @...
# ..@.
# ....
```

## How are They Used?

In [a recent study](https://www.researchgate.net/profile/Joao-Montandon/publication/400405267_Understanding_Type_Hints_in_Python_Libraries_and_Frameworks_Early_Insights/links/698276c45d60ab48356a9f61/Understanding-Type-Hints-in-Python-Libraries-and-Frameworks-Early-Insights.pdf),
researchers looked at 152 of the top python repositories on [GitHub](https://github.com/search?q=language%3Apython+stars%3A%3E1000&type=Repositories&ref=advsearch&l=&l=&s=stars&o=desc) and looked at how they used type hints.

They found that 91% of these top repos used at least one type hint.

That doesn't mean they were all used the same way. None of the repos use type hints on *every single function*. Most repos only used type hints for 13% of their code. The [openai-python](https://github.com/openai/openai-python) library used them the most, and they only covered 61% of their code.

The majority of these repos type hinted functions, but almost none type hinted variables:

```python
# Common:
def log_to_file(line: str) -> bool:
    logged_successfully = log(line, "my_log.txt")
    return logged_successfully

# Uncommon:
links: list[str] = ["https://google.com/"]
```

The types these repos hint also vary. Most type hints were builtins, less were local custom types, and almost none for external types.

```python
# Common: type hinting builtins
def log(line: str, level: int):
    ...


# Less common: type hinting custom types
class Logger:
    ...

class LoggerOptions:
    ...

def create_logger(name: str, options: LoggerOptions) -> Logger:
    ...


# Least common: type hinting external types
from openai import OpenAI

def create_ai_logger(name: str, ai_instance: OpenAI) -> Logger:
    ...

```

## What's the Developer Experience With Them?

While the study looked at where and how type hints were used, it doesn't include why a developer would use a type hint in one situation but not another.
It also doesn't include what work goes into maintaining type hints, or any developer's opinions on working with type hints.

I asked some friends of mine who've used python type hints in their libraries, and here's what they said:

**Did you like them?**

They loved them, and enjoyed the additional intellisense they provided.

**What did you hint?**

They all hinted every single method and function, but didn't hint variables.

**Is hinting worth it?**

They all agreed that it was and the amount of extra effort it takes is minimal.

**Is it more work to maintain?**

On the contrary, they each brought up that it made it easier to maintain. They cited that type hints require less documentation, and that they make it easier to work in groups.
