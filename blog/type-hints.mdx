Python has a type system, but variables and functions aren't statically typed. Accepting any data type can be a huge plus, especially for those learning to code. However, it can introduce unexpected bugs and take some getting used to if you’re coming from another programming language.

[PEP 484 - Type Hints](https://peps.python.org/pep-0484/) comes to the rescue! In this article, you'll learn what type hints are, why they're useful, and how they can help you with your code:


```python
def move_up(x: int, y: int) -> tuple[int, int]:
    return (x, y + 1)

new_x, new_y = move_up(2, 3)
```

## What Are Type Hints?

A type hint is a special [function annotation](https://peps.python.org/pep-3107/) that serves as a note to users, indicating the expected data type of a variable. These can be used on function parameters, return values, or on normal variables directly:

```python
# Parameters get a type hint with the `: <type>` syntax
def hello(name: str):
    print("Hello, " + name)

# Return values get a type hint with a hyphen and and arrow, `-> <type>`
def get_length(thing) -> int:
    return len(thing)

# Variables, like parameters, use the `: <type>` syntax
subscribers: list[str | int] = ["john.doe@email.com", 1234567890]
```

A Python type hint can be any valid data type, including compound types:

```python
class Grid:
    # A coordinate here is a tuple of exactly two ints, like (2, 5)
    def draw_point_at_coordinates(coords: tuple[int, int]):
        x = coords[0]
        y = coords[1]
        ...

my_grid = Grid()
coords = (2, 3)
my_grid.draw_point_at_coordinates(coords) # x = 2 and y = 3
```

Custom types and classes also work:

```python
# This function accepts a Grid object
# To use this type hint, Grid must be defined in this file somewhere
def show_grid(grid: Grid):
    ...

my_grid.draw_point_at_coordinates((1, 1))
show_grid(my_grid)
# @...
# ..@.
# ....
```

## Why Use Type Hints?

Python is a dynamically typed language, meaning that you don't assign specific static types to variables as you code, and a variable can change the type it's holding. While this creates an ease of use not found in other programming languages, it can lead to ambiguity in some situations.

Consider the following Python function, meant to add two numbers together.

```python
def add(a, b):
    return a + b

add(2, 2) # 4
add(3, 5) # 8
add(4, -2) # 1
```

Pretty straightforward.

However, because these variables can be of any type, this can cause errors if a user doesn't understand how the function works internally. Try out each of the following examples:

```python
def add(a, b):
    return a + b

add(2, 2) # 4
add("Hello ", "World!") # "Hello World!"
add("Hello", 2) # TypeError: can only concatenate str (not "int") to str
```

This function can add strings to strings, or integers to integers, but that isn't clear on the surface.

You don’t want to require your users to understand how all your functions work internally. To solve this, Python 3.5 was released in September 2015 with [PEP 484: Type Hints](https://peps.python.org/pep-0484/). In this example, users know this function is designed to expect only 2 integers and will return an integer.

```python
def add(a: int, b: int) -> int:
    return a + b
```

## How Are Type Hints Used?

In [a recent study](https://www.researchgate.net/profile/Joao-Montandon/publication/400405267_Understanding_Type_Hints_in_Python_Libraries_and_Frameworks_Early_Insights/links/698276c45d60ab48356a9f61/Understanding-Type-Hints-in-Python-Libraries-and-Frameworks-Early-Insights.pdf), researchers examined 152 of the top python repositories on [GitHub](https://github.com/search?q=language%3Apython+stars%3A%3E1000&type=Repositories&ref=advsearch&l=&l=&s=stars&o=desc) to assess how they used type hints. They found that 91% of these top repos used at least one type hint.

That doesn't mean they were all used the same way. None of the repos use type hints on *every single function*. Most repos used type hints in only 13% of their code. The [openai-python](https://github.com/openai/openai-python) library used them the most, and they only type-hinted 61% of their code.

They also found that the majority of these repos type-hinted functions, but almost none type-hinted variables:

```python
# Parameters and return values were commonly hinted (about 46% and 36%)
def log_to_file(line: str) -> bool:
    logged_successfully = log(line, "my_log.txt")
    return logged_successfully

# Variable type hints were not as common (about 6%)
links: list[str] = ["https://google.com/"]
```

The types being hinted in these repos also vary. Most type hints were builtins, fewer were local custom types, and almost none were for external types.

```python
# Common: type hinting builtins (about 73% used these)
def log(line: str, level: int): ...

# Less common: type hinting custom types (about 20% used these)
class Logger: ...

class LoggerOptions: ...

def create_logger(name: str, options: LoggerOptions) -> Logger: ...

# Least common: type hinting external types (about 4% used these)
import requests

def upload_log(log: str) -> requests.Response: ...

```

## What Do Developers Think About Type Hints?

While the study examined where and how type hints were used, it doesn't explain why a developer would use a type hint in one situation but not another. It also doesn't include what work goes into maintaining type hints, or any developer's opinions on working with type hints.

Here are the opinions of some Python developers on type hints:

**Do you like type hints?**

These developers unanimously love them and enjoy the benefits they provide. They pointed out the autocomplete, built-in warnings, and a reason to use them. One developer notes that type hints also made it easier to learn Python, coming from a different programming language.

**What do you hint?**

These developers type hint almost all of their hinted methods and functions, but don't hint variables. This is common among most popular Python repos.

**Is hinting worth it?**

These developers all agree that it is, and the amount of extra effort it takes is minimal.

**Are type hints more work to maintain?**

These developers believe that type hints make it easier to maintain code. One says type hints require less documentation, and another notes that they make it easier to work in groups.
