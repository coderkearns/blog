What are Type Hints?

Python is a dynamically typed language, meaning that you don’t assign specific static types to variable as you code. While this creates an ease-of-use not found in other programming languages, it can lead to ambiguity in some situations.

Consider the following Python function, meant to add two numbers together.

def add(a, b):
    return a + b

add(2, 2) # 4
add(3, 5) # 8
add(4, -2) # 1

Pretty straightforward.

However, because these variables can be any type, this can cause errors if we don’t understand what the function is doing internally.

def add(a, b):
    return a + b

add(2, 2) # 4
add("Hello ", "World!") # "Hello World!"
add("Hello", 2) # TypeError: can only concatenate str (not "int") to str

We don’t want to require our users to understand how all our functions work internally. To solve this, Python 3.5 was released in September 2015 with PEP 484: Type Hints. A type hint is a special function annotation that tells users what data type is required as an input or output:

def add(a: int, b: int) -> int:
    return a + b

Live demo

Output

You’ll notice that this doesn’t require users to obey the type hint, but it does communicate what the function author expects. This also will provide Intellisense (autocomplete and hover-tooltips) in most code editors.

A python type hint can be any valid data type, including compound types:

class Grid:
    def draw_point_at_coordinates(coords: tuple[int, int]):
        x = coords[0]
        y = coords[1]
        ...

my_grid = Grid()
coords = (2, 3)
my_grid.draw_point_at_coordinates(coords) # x = 2 and y = 3

Custom types and classes also work:

def show_grid(grid: Grid):
    for row in grid:
        print(row)

my_grid.draw_point_at_coordinates((1, 1))
show_grid(my_grid)
